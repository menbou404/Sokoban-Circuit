# Codexに任せる実装範囲

このプロジェクトでは、ファイル構造や内部設計をCodexに一任する。

その代わり、ゲームの挙動仕様だけは固定する。

## Codexが自由に決めてよいこと

- ファイル構造
- フォルダ構造
- シーン構成
- ノード構成
- クラス分割
- 関数名
- 変数名
- 描画方式
- TileMapLayerを使うかどうか
- Node2Dの描画を使うかどうか
- デバッグ表示の配置
- ステージデータの持ち方
- テスト用ステージの追加

## ただし守ること

ゲーム状態は、画面表示ではなく、マス目座標のデータとして管理する。

プレイヤーとブロックは、常に整数マスに存在する。

押し判定は物理エンジンに任せない。

信号計算は毎手ごとにゼロから再計算する。

AND/ORの入力方向と出力方向は、最小試作品では固定する。

## 推奨する内部データ

Codexは別の設計を選んでもよいが、次のようなデータを持つと実装しやすい。

```gdscript
var grid_width: int
var grid_height: int
var player_cell: Vector2i
var walls: Dictionary
var wires: Dictionary
var sources: Dictionary
var lamps: Dictionary
var blocks_by_cell: Dictionary
var powered_cells: Dictionary
```

## 推奨する責務分離

必須ではないが、次の責務分離が望ましい。

- 入力処理
- 移動判定
- ステージ読み込み
- 回路計算
- 描画
- リセット処理

## 最小構成の考え方

Godotのシーンファイルを手で複雑に作る必要はない。

最初は、1つのメインシーンと数個のスクリプトでよい。

すべてを1ファイルに詰め込むのは避けた方がよいが、最小試作品として動作確認できるなら、過度な分割も不要である。

## 実装判断の優先順位

1. 完了条件を満たす
2. バグを追いやすい
3. Godotで開きやすい
4. 後から拡張しやすい
5. 見た目がきれい

見た目の美しさは最優先ではない。
